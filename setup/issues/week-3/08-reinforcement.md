# [Week 3] Reinforcement — Said it twice? Then it belongs in a file

**Pedagogy:** Reinforcement · **Milestone:** Week 3
**Prerequisite:** Week 3 Knowledge issue complete.

## Why

The rule of twice only works if you notice the second time, and noticing is exactly what
you stop doing when you are busy. Repetition feels like work getting done. That is why the
habit needs a standing instruction rather than good intentions.

So you write it into your global `~/.claude/CLAUDE.md`, where every session you ever start
will read it. The point is repetition across months, not a note you read once.

## The Task

Add a paragraph to `~/.claude/CLAUDE.md` (global scope, not the project file) that makes
Claude surface this week's ideology unprompted, in every future session.

It should cause Claude to:

- **Count the repeat.** When an instruction has been given twice, say so, and name which
  artifact type it belongs in: settings, permission rule, command, hook, skill or
  CLAUDE.md.
- **Apply the two questions.** Ask whether it must be impossible to skip, and whether it is
  needed always or only sometimes, then place it accordingly.
- **Name the scope.** Say whether the artifact belongs at user, project or local scope, and
  what committing it asks of teammates.
- **Distinguish asking from enforcing.** When prose is being used to guarantee something,
  say that only a permission rule or a hook can actually refuse.

Write it in your own words. Copying the bullets verbatim produces something that reads like
a checklist and gets ignored. Keep it short: a long paragraph competes for attention with
everything else in the file.
